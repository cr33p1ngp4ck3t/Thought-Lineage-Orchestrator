# Backend hardening implementation plan

Implement the approved review and Datafactor recommendations in the existing Flask service.

1. **Offline regression tests:** add pytest, pytest-mock, coverage, Ruff and test discovery configuration. Fake the Gemini boundary and forbid network access and real environment credentials. Cover signature serialization, lineage, agent sequencing, detector and synthesis failures, API validation and credential isolation. Run the regressions before implementing their fixes.
2. **Request isolation:** introduce `src/gemini_client.py` with an instance-owned SDK client; inject it through the orchestrator, all agents, detector and synthesizer. Remove import-time/global SDK configuration. Keep graph data in each POST response; return 410 from the obsolete shared graph endpoint. Close the request client on success and failure. Test sequential and overlapping requests with different credentials.
3. **Trust boundaries and failures:** add Pydantic request/output validation, typed provider/signature/detection errors, explicit synthesis fallback metadata, safe logging and `/health`. Bound request size and problem length, reject unsupported modes/types, and never echo keys or provider error text. Test malformed JSON, provider failures, malformed model output and legitimate requests.
4. **Safe rendering:** escape all generated text before HTML interpolation and restrict dynamic CSS classes. Preserve arbitration metadata and show synthesis degradation. Exercise an HTML injection payload and ordinary results in the browser.
5. **Reproducibility:** standardize Python 3.13; generate runtime/development locks, align serverless requirements, add push/PR CI for Ruff, offline pytest and container health, weekly Dependabot, Dockerfile and dockerignore. Preserve the existing live demos as explicitly opt-in examples outside pytest discovery.
6. **Onboarding:** update README, QUICKSTART, DEPLOYMENT, `.env.example`, CONTRIBUTING and CHANGELOG with exact setup/test/lock/container commands and API compatibility changes. Use a clean virtualenv to verify installation from locks, run lint and tests, then review the complete diff.

Acceptance: no API key/network is needed for tests; no request can reuse another request's key or graph; malformed inputs return JSON 4xx; detection errors are never reported as successful absence of conflict; generated HTML stays inert; local fresh-install checks pass. Hosted Actions and live Gemini verification require their actual environments and must not be claimed without execution. Real future history and payout are not implementation deliverables.
